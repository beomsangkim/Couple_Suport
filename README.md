# 함께살이 (Couple_Suport)

함께 사는 두 사람이 생활비·집안일·생활 약속을 함께 정하고, 상황이 바뀌면 다시 조정하는 앱의 **프로토타입**입니다.

- [`docs/brief-v1.0.md`](docs/brief-v1.0.md): 초기 제품·UI·보안 명세
- [`docs/brief-v1.1-review.md`](docs/brief-v1.1-review.md): v1.0 검토와 보안 우선 개정안 (이 프로토타입의 기준)

## 이 프로토타입이 보여주는 것

| 영역 | 구현 | 개정안 근거 |
|---|---|---|
| 약속 | 제안(보내기 = 제안자 동의) → 상대 동의 → 적용/적용 예정, 수정 제안, 제안 거두기, **혼자 즉시 철회** | S-2, §6.2 |
| 동의 진정성 | 화면이 받은 **내용 해시**와 일치할 때만 동의, 금전 약속 동의는 **단계 인증** | S-4 |
| 생활비 | 지출 기록(약속대로/반반/직접), 나머지 1원은 결제자 부담, 멱등 키, 버전 충돌 감지 | §4, §11.3 |
| 신뢰 | 작성자만 수정, 상대는 ‘확인 필요’ 표시만, 확인 필요가 있으면 정산 불가 | §6.3 |
| 정산 | 두 사람이 같은 스냅샷을 확인해야 확정, 중간에 지출이 바뀌면 다시 확인 | §11.3 |
| 소득 계산기 | 브라우저 메모리에서만 계산, **5% 단위 반올림**, 서버로 보내지 않음 | §5 |
| 집안일 | 완료 기준·반복 요일, 완료는 **날짜만** 저장, 담당 교환 요청 | S-3 |
| 감시 신호 금지 | 읽음 표시·접속 상태·완료 시각·위치 없음 (테스트로 검사) | S-3 |
| 초대 | 링크 + **양쪽 확인 코드**, 토큰은 HttpOnly 쿠키로 옮기고 주소창에서 제거, 5회 오입력 시 취소 | S-9 |
| 연결 해제 | 혼자서·단계 인증 없이, 두 사람 모두 30일 읽기 전용, 글 즉시 숨기기, 재초대 차단 | S-10 |
| 대화 카드 | 성생활·피임·건강 등은 저장 기능 없는 카드로만 | S-6 |
| 웹 보안 | nonce 기반 CSP, `frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, HttpOnly 세션 쿠키, 모든 화면 동적 렌더링(공유 캐시 없음) | S-8 |
| DB | Supabase용 마이그레이션: RLS, 열 단위 권한, `security_invoker` 뷰, RPC 전용 쓰기, 정원 제약 | S-7 |

## 실행

```bash
npm install            # .npmrc에서 설치 스크립트를 막아 두었다(ignore-scripts)
npm run dev            # http://localhost:3000
```

가상 사용자를 골라 들어갑니다. 두 사람의 화면을 같이 보려면 일반 창과 시크릿 창에서 각각 로그인하세요.

- **민 / 지우**: 같은 공간. 지우가 보낸 ‘생활비 50:50’ 제안이 민의 답변을 기다리는 상태
- **하늘 → 해솔**: 하늘이 공간을 만들고 초대, 해솔이 링크를 열어 확인 코드로 연결
- **서준**: 다른 공간. 공간 격리 확인용

## 검증

```bash
npm run typecheck
npm test               # 서비스 계층 보안·계산 테스트 (Vitest, 38개)
npm run test:db        # PostgreSQL RLS 보안 테스트 (임시 클러스터, 44개 항목)
npm run build && npx next start -p 3100 &
NODE_PATH=$(npm root -g) node scripts/e2e-smoke.mjs http://localhost:3100   # 브라우저 흐름 + CSP 위반 + 320px 확인
```

`test:db`는 로컬 PostgreSQL 15 이상이 필요합니다. `db/tests/00_supabase_shim.sql`이 Supabase의 `auth.uid()`·역할을 흉내 냅니다.

## 구조

```
src/server/services/   # 모든 인증·인가·검증이 일어나는 곳. 세션 ID만 받고 사용자 ID는 받지 않는다
src/server/store.ts    # 프로토타입용 메모리 저장소 (실제로는 db/ 의 PostgreSQL로 대체)
src/app/actions.ts     # Server Action. 입력을 서비스에 넘기기만 한다
src/proxy.ts           # CSP nonce. 권한 경계가 아니다
db/migrations/         # Supabase용 스키마 + RLS + RPC
tests/                 # SEC-xx 시나리오
```

## 프로토타입의 한계 (실제 서비스 전 필요한 것)

- **인증은 가짜입니다.** 가상 사용자 선택 + 세션 쿠키입니다. 패스키·이메일 복구·단계 인증은 시뮬레이션입니다(S-5).
- **데이터는 서버 메모리에 있습니다.** 서버를 재시작하면 처음 상태로 돌아갑니다. 앱은 아직 `db/`의 PostgreSQL에 연결돼 있지 않습니다. DB 계층은 정책과 테스트만 있습니다.
- DB 계층에는 아직 초대·정산·집안일 테이블이 없습니다(서비스 계층에만 구현).
- 요청 제한(rate limit), 알림 발송, 개인정보 처리방침·동의 화면, 운영 로그 마스킹, 백업 정책은 구현하지 않았습니다(S-11, S-12).
- 접근성은 레이블·포커스·색 외 식별·320px 폭을 반영했지만, 스크린리더와 대비는 **수동으로 검증하지 않았습니다**.
- DB의 내용 해시(`app.version_hash`)와 프로토타입의 해시(`canonicalJson`)는 계산 방식이 다릅니다. 실제 구현에서는 DB 쪽을 기준으로 삼습니다.
